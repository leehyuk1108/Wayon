# Hylink approved dashboard — 1.5.0 / versionCode 7

## Scope

Implements the user-approved `design/cloud-overview/` layout in the real Android
Hylink app. My Traverse New, Wayon Cloud server, comma uploader and vehicle
controls are unchanged. Debug package: `app.hylink.mobile.debug`.

Apple Design principles informed the information hierarchy, progressive
disclosure, large text reflow, touch targets and separate map annotations.
This is an Android implementation, not an iOS framework port.

## Visible behavior

- Now / Records / Vehicle bottom tabs; no top brand or theme/settings menu.
- Map takes spare height. One overlapping recent-drive/media panel meets tabs.
- Now shows only the vehicle's last received GPS. No invented default point.
- Tap map: full-screen map with a separate blue phone dot and car marker.
  Closing removes the phone dot. Vehicle / My location / Fit both controls.
- Missing readings stay unknown. Old readings are labeled last received;
  onroad updates older than 60 seconds and offroad updates older than 15 minutes
  receive delay warnings. These are presentation rules, not a safety assessment.
- Records show real trip, parking photo, saved clip/photo and impact metadata.
  Missing/failed history is distinguished from a successfully received empty list.
- Detailed device telemetry is disclosed on the Vehicle tab, not added to home.
  Connection key management and refresh remain in Vehicle for onboarding/recovery.
- No fuel, TPMS or lock claims are inferred from unsupported fields.

## Data and retained functionality

Native `onHylinkData` feeds the production presentation model; no fixture import
or scenario switch exists in the app entry point. Native endpoint cache,
30-second foreground polling and history/backoff policy remain unchanged.

Trip details use `/api/trips/{id}` and render the saved GPS route. Photos use
authenticated snapshot/live-capture endpoints and bounded object-URL caching;
unopened media isn't downloaded. Saved video and 360-degree live use the existing
`wayon_live.js` decoder/player. SSH uses the existing terminal module and relay,
with a stricter client requirement for a recent explicit offroad state. The
server's existing offroad gate is not removed. SSH commands remain user initiated.

Key replacement/logout invalidates media requests, clears vehicle/map content
and closes sessions. Late trip responses are fenced by key and request sequence.
The app does not clear Android app data during installation.

## Phone location and map privacy

Foreground coarse/fine permission is requested only when the full map needs a
phone location. Native `LocationManagerCompat` obtains one fix; a 15-second
timeout, dialog close and lifecycle cancellation prevent background tracking.
The phone fix isn't saved or sent to Wayon. Closing ignores late callbacks.
Permission denial, timeout and unavailable providers are explicit states.

Map requests necessarily reveal the viewed area to the map provider, including
the phone area when users choose to display it. No Wayon key is attached to map
requests. MapLibre GL JS **5.12.0** JS/CSS and license are bundled locally;
no executable JavaScript is fetched from a CDN inside the privileged WebView.
Styles/tiles/fonts use `https://tiles.openfreemap.org/styles/positron`.
The small information control retains OpenMapTiles/OpenStreetMap attribution.
External attribution opens only allowlisted HTTPS hosts in the browser.

## Build and validation

JDK 17, Android SDK 36, existing Gradle wrapper:

```sh
./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug
node scripts/check-cloud-design.mjs ../app/src/main/assets/hylink-model.js
# Dedicated Chrome --remote-debugging-port=9338, preview server on 4198:
node scripts/check-production-ui.mjs
```

The dedicated browser tests use only synthetic telemetry and test coordinates.
They cover callbacks, missing data, bundled vector map, location success/denial,
home/full-map separation, trip detail, key clearing, and 24 width/text/tab layouts
(320/390/768/1100 pixels, 100%/200%, three tabs).

Android contract tests: 4 passed. Production presentation tests: 18 passed.
Build succeeds. Existing file-URL deprecation/SDK tooling warnings are retained;
universal file-origin access is **not** enabled to work around them.

Device check: original app certificate matched; `adb install -r` succeeded with
version 7 and existing login. Real state/trip/photo/clip lists arrived without
endpoint errors. Physical Android screenshot verified rendered roads and vehicle
marker; CDP screenshots alone can omit WebGL content and aren't sufficient.
Now had one vehicle marker and no phone dot; bottom panel met tabs without a gap.

Actual phone permission/GPS, media opening, and final build readback results are
tracked separately during device acceptance. Installation or mocked callbacks
alone must not be called successful in-vehicle operation. Live/SSH/vehicle driving
are not automatically exercised by these test scripts.

## Signing and distribution boundary

Use the same existing signing certificate for data-preserving updates. Signing
material is held outside the project with restrictive permissions; never commit
it or credentials, APKs, device photos or private coordinates. The currently
installed Dev app still uses its original debug certificate. Public/store release
signing, account onboarding, fleet/provider capacity and long-term field validation
are separate release work, not completed by this UI change.
